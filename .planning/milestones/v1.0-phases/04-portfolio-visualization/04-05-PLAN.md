<objective>
Close G-04-2a and G-04-2b, which share one root cause: Recharts 3.x turns every cartesian chart
into a focusable keyboard widget by default, and the watchlist sparkline is a DOM descendant of
the already-focusable row. Each row therefore owns two tab stops, so one Tab lands back inside
the row it came from, Enter there re-selects the already-selected ticker (a silent no-op), and
the browser paints a heavy white ring around the 114x20 mini chart that reads as an empty box.

Purpose: keyboard activation of the watchlist is a stated Phase 4 success criterion and the user
reported it as simply not working. The debug session proved the row's own handler is correct and
that the sparkline draws correctly the instant focus leaves it — so one change at the chart's
focus surface closes both reported symptoms, and one verification covers both.

Output: a sparkline that draws but cannot take focus; a single on-theme focus ring for the chart
surfaces that deliberately stay focusable; and the focusable-surface decision recorded in code
for all four chart components rather than left implicit.
</objective>
