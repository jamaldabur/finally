<planner_decisions>
- **P-01 — test-support location.** Shared test doubles live in `frontend/test-support/`, not
  `frontend/lib/test-support/` (06-PATTERNS.md) and not `frontend/test/` (06-RESEARCH.md). `lib/` is
  the application's import surface and test doubles must not sit in it; a folder named `test` inside
  `frontend/` invites confusion with the top-level E2E `test/` directory (RESEARCH Pitfall 4); and a
  single dedicated directory is one `.dockerignore` line.
- **P-02 — `vitest.config.mts`, not `.ts`.** The Vitest guide bundled with this project's installed
  Next.js (`frontend/node_modules/next/dist/docs/01-app/02-guides/testing/vitest.md`) names the file
  `vitest.config.mts`. `frontend/package.json` has no `"type": "module"`, and `@vitejs/plugin-react`
  6 and `vite-tsconfig-paths` 6 are ESM-only; the `.mts` extension makes the config an ES module
  regardless. `tsconfig.json` already includes `**/*.mts`, so typecheck covers it.
- **P-03 — pin `vite` explicitly.** `vitest@5.0.2` declares `vite` (`^6.4 || ^7 || ^8`) as a
  non-optional peer and `@vitejs/plugin-react@6.1.1` requires `vite ^8`. Pinning `vite@8.3.1` as a
  direct devDependency guarantees one Vite copy, which is what keeps the plugins' types assignable in
  `vitest.config.mts`. `vite` is not in RESEARCH.md's legitimacy table and the planner's own check
  returned `SUS (too-new)`, so it is on the checkpoint list.
- **P-04 — the EventSource stub needs statics and an `open()` helper.** `priceStore.tsx`'s grace
  timer reads `es.readyState !== EventSource.OPEN`. RESEARCH.md's Pattern 1 stub has no static
  `OPEN`, so `EventSource.OPEN` would be `undefined` and every grace timer would report
  `disconnected` even when open. It also has no way to fire `onopen`. Both are added here.
- **P-05 — test code stays out of the Docker build context.** The root `.dockerignore` gains
  exclusions for test files, test support, Vitest config and the top-level `test/` directory. This
  keeps test doubles out of every image layer, and it decouples the E2E plan's image build (06-05)
  from 06-03 and 06-04, which add test files in parallel with it.
</planner_decisions>
