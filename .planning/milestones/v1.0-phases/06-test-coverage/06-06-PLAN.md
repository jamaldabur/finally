<objective>
## Phase Goal

**As a** developer maintaining FinAlly, **I want to** run backend, frontend and end-to-end suites
that exercise the whole trading loop, **so that** I can change any layer and know within minutes
whether watch, trade, chat and portfolio still work together.

This plan completes TEST-05 on top of 06-05's harness: buy, sell, watchlist add/remove, visualization
rendering and mocked chat trade execution — the full agentic loop (watch -> decide -> chat ->
execute -> see it in the portfolio) driven through a real browser against the real Docker-built app.

Two constraints shape every spec. First (P-10), all specs share one database and run serially in
file-name order, so each spec measures its own before/after values rather than assuming seed state.
Second (D-07 and P-06), watchlist changes and chat trades are driven only by phrases the backend's
deterministic mock actually maps to actions — "add PYPL to my watchlist", not "add PYPL" (RESEARCH
Pitfall 1) — and those phrases are checked against `build_mock_response` directly before the slow
browser run.

Output: four spec files, an extended helpers module, and a green 13-test E2E suite.
</objective>
