<objective>
## Phase Goal

**As a** developer maintaining FinAlly, **I want to** run backend, frontend and end-to-end suites
that exercise the whole trading loop, **so that** I can change any layer and know within minutes
whether watch, trade, chat and portfolio still work together.

This plan is the backend third of that story (TEST-01, TEST-02, TEST-03). Per D-01 it is an
audit-and-close-gaps task, not a new suite: 228 backend tests already exist and RESEARCH.md read
their bodies against the requirement wording. The planner re-ran that audit against the actual
test names and found **two** genuine gaps, not one:

1. No test asserts the 422 that `WatchlistAddRequest.ticker`'s `Field(min_length=1)` produces for
   an empty ticker (RESEARCH.md's finding, TEST-03).
2. No test sells below average cost. Every existing sell (`test_sell_does_not_change_avg_cost`,
   `test_sell_credits_cash_and_reduces_position`, `test_sell_all_closes_position`, and the rest)
   sells at or above the buy price, yet PLAN.md section 12 names "selling at a loss" explicitly as a
   backend portfolio edge case (TEST-01). This is planner decision **P-14**.

Purpose: turn the roadmap's backend success criteria 1-3 from "probably covered" into "named,
passing tests prove it", while touching nothing under `backend/app/`.

Output: three new tests in two existing test files, and an audit matrix recorded in the SUMMARY
that maps every TEST-01/02/03 behavior to the test that proves it.
</objective>
