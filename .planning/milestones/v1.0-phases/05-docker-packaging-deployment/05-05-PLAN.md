<objective>
**As a** user of FinAlly, **I want to** start the entire application with a single command and have
my data persist across restarts, **so that** I get the one-command trading terminal Phase 5
promises. On Windows, that also means that no malformed flag can quietly stop my running app or
quietly throw away the rebuild I asked for. This includes a flag with a stray trailing colon.

(The user story is carried verbatim from 05-04-PLAN.md, which framed the same ROADMAP goal. The
ROADMAP `**Goal:**` line itself is not written in user-story form.)

This is a gap-closure plan (Wave 5) for one gap. 05-VERIFICATION.md scores 13/14. Its failed truth
14 is the colon-token bypass. 05-REVIEW.md (CR-01, WR-01) found the same defect independently, and
05-SECURITY.md reopened T-05-08 because of it (status draft, threats_open 1, PHASE 5 SECURITY
BLOCKED).

Both launchers validate only `$args`. PowerShell's `-File` command-line parser silently drops a
dash-prefixed, colon-suffixed, valueless token before the script body runs. So `$args.Count` reads
0 for `-Foo:`, which cannot be told apart from a bare invocation. The verifier reproduced this
live:
- `stop_windows.ps1 '-Foo:'` stopped a running container with rc=0.
- `start_windows.ps1 '-Build:'` discarded the rebuild request with rc=0.

**Plan-time grounding.** Everything below was done with scratchpad probes and temp copies. Nothing
in the repository was modified. See `<grounding>` for the full probe table.
- The swallowed token is invisible to `$args`, `$MyInvocation.UnboundArguments`,
  `$PSBoundParameters` and `$MyInvocation.Line`.
- `[Environment]::GetCommandLineArgs()` still shows it, as the host argv element after the
  script's own path.
- `$MyInvocation.Line` is empty exactly when the host started the script from its own command line
  (`-File`), and holds the calling line in-session. That makes it a clean discriminator.
- `[System.IO.Path]::GetFullPath` of the host argv's script-path element equals `$PSCommandPath`
  for every path form tried, including 8.3 short names.
- **New shape found at plan time:** `-File start_windows.ps1 -Build -Foo:` gives `$args = -Build`
  only. 05-04's guard therefore accepts it as a rebuild while silently dropping `-Foo:`. The fix
  below closes this too.
- A prototype of the fix, run against temp copies of both launchers, turned every colon-shape row
  from RED to GREEN. It left every 05-04 row and every accepted form unchanged.

**The fix follows the direction both source documents recommend.** 05-VERIFICATION.md `missing[0]`
and 05-REVIEW.md CR-01 both call for cross-checking the host command line against `$args` and
rejecting raw tokens that end in `:`. It is not a new mechanism.

One variant of the review's wording needs care: "reject any `$args` element whose string form ends
in `:`". That cannot work on its own, because the swallowed token never reaches `$args`. Any
`$args` element that does end in a colon is already rejected by 05-04's exact match. So the
trailing-colon rule is applied to the raw host command-line tokens instead.

**Scope of the closure records.** The same code fix is what closes truth 14 (DEPLOY-03) and
T-05-08. The closing record, however, belongs to the owning workflows:

- 05-SECURITY.md is flipped by re-running `/gsd-secure-phase 05`, as its own ENFORCING GATE
  instructs.

This plan edits neither file. It records the evidence both auditors need in the SUMMARY. This is

Other signals that were probed:
- **`$MyInvocation.Line`:** empty under `-File`. In-session it holds the calling line, including
  under `-Command` and when called from another script that was itself started with `-File`. This
  plan uses it as the `-File` discriminator.
- **`$MyInvocation.UnboundArguments` and `$PSBoundParameters`:** both empty for `-Foo:` under
  `-File`. Not usable.
- **Script-path identity:** `[System.IO.Path]::GetFullPath(<argv element>)` equals `$PSCommandPath`
  for every form of the `-File` target that was tried:
  - `scripts/x.ps1` relative from the repo root;
  - `C:/.../x.ps1`;
  - `C:\...\x.ps1`;
  - an 8.3 short path (.NET Framework expands the short names);
  - `.\x.ps1` relative from the scripts directory;
  - the `-f`, `-fi` and `-fil` abbreviations of `-File`.
- **GetFullPath on a colon token:** `GetFullPath('-Foo:')` throws a MethodInvocationException. It
  must be caught, or it becomes a terminating error under `$ErrorActionPreference = "Stop"`.

Line-gate proof. The case is a `-File` wrapper script that receives the launcher's path as its own
argument and calls `& $args[0] -Build`. Its host argv therefore contains the launcher's path
followed by nothing:
- With the `$MyInvocation.Line` gate, the prototype accepts it: it reaches the `.env` guard.
- With the gate removed, the prototype falsely rejects it with the usage line.

So the gate is load-bearing.

Docker shim. A `docker.cmd` placed first on PATH logs every invocation and exits 1. PowerShell
resolves `docker` to it before the real `docker.exe`. It turns "no docker command runs" into a
directly countable `docker_calls` value, and it makes the stop matrix safe even if FinAlly happens
to be running.

- **Start path-form matrix:** `-Foo:` and `-Build:` show usage=0 env_guard=1 in all three forms.

- **Structural gates:** host_argv_reads=0 and GUARD_MISPLACED for both scripts.
