**As a** user of FinAlly, **I want to** start the entire application with a single command and have
my data persist across restarts, **so that** I get the one-command trading terminal Phase 5
promises. On Windows, that also means that no malformed flag can quietly stop my running app or
quietly throw away the rebuild I asked for. This includes a flag with a stray trailing colon.

(Carried verbatim from 05-05-PLAN.md, which carried it from 05-04-PLAN.md. The ROADMAP `**Goal:**`
line for Phase 5 is not written in user-story form, so no new story was invented here.)

This is a gap-closure plan (wave 6) for one gap. 05-VERIFICATION.md (2026-09-27 pass) scores 13/14.
Its failed truth 14, the two Anti-Patterns Found blocker rows and DEPLOY-03 NOT SATISFIED all name
the same defect, which 05-REVIEW.md's 2026-09-27 pass found as CR-01 (stop) and WR-01 (start).
05-05 added a host-argv cross-check to close the colon-token bypass. In both launchers `$ArgsIntact`
starts true and is only ever set false inside a block that runs when `$RawArgs` was found. When
`$MyInvocation.Line` is empty but the anchor search finds no host argv token whose full path equals
`$PSCommandPath`, `$RawArgs` stays `$null` and the block is skipped. The guard then trusts `$args`
alone, which is exactly the pre-05-05 bypass.

**The vertical slice (Task 1, the tracer):** an unrecognised argument is rejected before any docker
command runs, for every token shape, including when the anchor search cannot find a match. The path
is: the command line, the PowerShell host, step 1 of both launchers, and the docker CLI boundary
(behind a counting shim, and live against the real daemon). Tasks 2 and 3 expand from that slice.
Task 2 holds the review's lower-priority cleanups (IN-01, IN-02, IN-03 and WR-02) plus the full live
sequence against the final scripts. Task 3 records the resolutions in 05-REVIEW.md.

**The fix is 05-REVIEW.md CR-01's own sketch, applied identically to both files** (WR-01 asks for
this). Under an empty `$MyInvocation.Line`, a `$null` `$RawArgs` rejects, a count mismatch rejects,
and otherwise the trailing-colon test runs. The one placement change: the sketch's three-way
decision goes inside the existing `$MyInvocation.Line` gate rather than a second copy of it. The
file then tests the discriminator once, and every `$ArgsIntact` decision lives in one block. This
is behaviourally identical to the sketch.

**This reverses a 05-05 plan-time decision.** 05-05-SUMMARY.md A6 and 05-05-PLAN.md T-05-19 chose
fail-open, preferring that to a false rejection. The review and the verifier both rule that
fail-open is a blocker, so this plan fails closed and restates T-05-19's residual honestly (see
`<threat_model>`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user command line → host (the powershell.exe or pwsh `-File` parser, or a command-API host such as an in-process runspace or a background job) → launcher script body | A `-File` host can drop tokens before `$args` is populated (dash-prefixed, colon-suffixed, valueless tokens). A command-API host passes arguments as objects and never puts the script on the process command line. Both leave `$MyInvocation.Line` empty. The launcher cannot tell them apart from the host argv alone, which is why a missing anchor must fail closed |
| launcher → Docker daemon state | A misread invocation changes real state. On stop it reaches a live `docker stop` against a running container; on start it silently turns a rebuild request into a plain start |
