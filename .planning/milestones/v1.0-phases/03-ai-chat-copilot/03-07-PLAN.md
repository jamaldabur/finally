<objective>
Close G-03-4: make the collapsed chat rail an actual rail. The user reported a broken-looking
rotated label, but the debug session drove a real headless browser against the production build
and measured the thing they were looking at: a 48x59px chip in the top-right corner, 782px
shorter than the column beside it.

Purpose: the primary cause is a full-height utility on the panel's outer wrapper. A percentage
height there resolves against a row whose specified height is auto, so it degrades to content
height — and, worse, having a non-auto computed cross size switches off the item stretch that is
the only mechanism giving `main` and the left column their full height. One property, whole
defect: forcing the wrapper to auto height in the live page made it jump from 59px to 841px,
exactly matching its sibling. This predates Plan 03-05 — the utility has been there since Plan
03-03 — so this is not a regression from the last gap-closure round, and the earlier debug
session's claim that the rail was "full-column height" was an unverified inference, not a
measurement. The rotated label is a real but secondary contributor: the CSS applies exactly as
authored and its metrics are identical to horizontal, but it puts a rotated word under an
upright chevron and reads as jammed only because the chip left it flush against the border.
Fixing the orientation alone still measured as a 48x50px chip.

Output: an amended `03-UI-SPEC.md` whose rail-label row and Dock placement bullet stop
prescribing the rotated label and start stating the rail's height explicitly, and a
`ChatPanel.tsx` whose wrapper stretches instead of shrinking and whose label reads upright.
</objective>
