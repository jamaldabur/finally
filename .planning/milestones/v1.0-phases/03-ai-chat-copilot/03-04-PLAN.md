<objective>
Make the outcome of every AI-requested action visible and honest: one badge per action,
carrying the backend's own verdict and its own verbatim rejection text — never the model's
opinion of what happened. Then finish the panel: collapse rail, scroll-to-latest pill, and
a watchlist that reflects what the assistant just changed.

Purpose: CHAT-04 is the requirement that makes the agentic loop trustworthy. The model
writes its `message` before anything executes, so the only true account of what happened is
the structured data the backend computed. This plan is where that data becomes something the
user reads, deliberately positioned outside the chat bubble so the two can never be
confused.

Output: `ActionBadge.tsx`, badge stacks wired into the message list, the collapse rail and
unread dot, the scroll-to-latest pill, and the watchlist refresh hook.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend `reason` string → badge render | Server-authored text (which may embed a ticker the user or model supplied) is rendered into the DOM |
| `outcome` field → success/failure indicator | The only source of truth for what actually happened crosses into the visual affordance the user trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-15 | Spoofing | `ActionBadge.tsx` outcome indicator | high | mitigate | The badge's colour, glyph and `role="alert"` are driven solely by `action.outcome`, the field the backend computed from the real `TradeResult`. Nothing in the badge reads, parses, or is influenced by the model's `message` prose, so a prompt-injected claim of success cannot produce a green badge. A negative grep asserts no raw-HTML injection anywhere under `frontend/components/chat/`. |
| T-03-16 | Tampering | verbatim `reason` rendering | medium | mitigate | `reason` is rendered as JSX children with no JS string transformation; a negative grep asserts the badge applies no case change, slice, or substring. This preserves the exact rejection text and simultaneously removes the only place a truncation could hide the real cause of a failure. |
| T-03-17 | Information Disclosure | `reason` strings shown in the UI | low | accept | Backend rejection text embeds portfolio figures (available cash, held shares). Accepted: this is the user's own data in a single-user local app, and the same figures are already displayed in the header and positions table. |

## Canon referrals (not minted as bespoke prohibitions)

- XSS through server- or model-authored strings is canon — covered by `/gsd-secure-phase`, React's default escaping, and the raw-HTML negative grep (T-03-15).
</threat_model>
