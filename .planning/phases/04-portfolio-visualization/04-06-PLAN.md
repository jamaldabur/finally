<objective>
Close G-04-3: the heatmap suppresses a tile's P&L percentage on tiles that have plenty of room
for it. `PCT_MIN_WIDTH = 64` is a fixed pixel constant that exceeds the label's real rendered
width — measured live at 30-46px for a percentage at 10px/600 — and Recharts' squarify lays this
panel's tiles out as full-height narrow columns because the `h-60` shell keeps the chart box
short. Low-weight holdings land in the dead band between "fits the text" and "clears the gate",
so a 60x158px tile holding 27.5% of the portfolio shows its ticker and nothing else.

Purpose: the UI-SPEC conditions the drop on the label genuinely not fitting. This is an
implementation defect against that spec, not spec'd behaviour the user dislikes — and 04-RESEARCH
pre-flagged the constants as unverified against real glyph metrics, with 04-03-SUMMARY recording
them as "tunable at UAT". This is that tuning, done properly: gate on the text, not on a rectangle.

Output: a `labelFits()` helper and two per-glyph width constants carrying the measured evidence in
their comment; both label gates rewritten to consult them; a corrected vertical threshold; and the
drop order made explicit so the overflow rule still holds where it is genuinely true.
</objective>

<planner_assumptions>
1. **An estimate, not a measurement.** The gap offers "estimated or measured". A real measurement
   needs a ref on each `<text>`, a `getComputedTextLength()` read and a second render pass, inside
   a function Recharts calls per tile on every data change — a structural change far larger than
   the defect, in a component with no test coverage. Two constants derived from the debug
   session's own live measurements, set conservatively, close the gap with a fraction of the risk.
   A negative grep forbids the measurement approach sneaking in, so the choice is explicit.
2. **Two constants rather than one.** The measured evidence separates cleanly: uppercase ticker
   glyphs advance 6.0-7.0px, digits and signs 5.1-5.7px. A single conservative constant of 7
   would also fix the reported NVDA case, but it would falsely drop a seven-character percentage
   such as "+17.27%" on that same 60px tile, where the real string measures 36.5px against 44px of
   available room. Since AAPL was holding exactly that kind of figure during UAT, one constant
   would have traded the reported false drop for a near neighbour of it.
3. **`TICKER_MIN_HEIGHT` is left at 26 deliberately.** The gap's `missing` list names only
   `PCT_MIN_HEIGHT`, the debug session confirms no observed tile ever failed on the ticker height,
   and the same derivation lands near 24 — close enough that changing it would be churn against no
   evidence. Recorded rather than silently skipped.
4. **The panel's fixed `h-60` shell is not changed.** The debug session names the short chart box
   as a contributing condition, since it is what makes squarify emit narrow full-height columns.
   But it is a deliberate UI-SPEC layout decision (two equal `h-60` panels side by side), it is
   shared with the Portfolio Value panel, and the root cause is explicitly the width constants,
   not the panel height. Changing the layout to work around a label bug would be the larger, more
   destabilising fix.
5. **Out of scope, stated rather than dropped: keyboard reachability of tiles.** Recharts' Treemap
   renders no focusable root (confirmed in the sibling Plan 04-05), so a tile with no inline text
   is reachable only by hover. That is a pre-existing limitation of the UI-SPEC's tooltip-fallback
   rule rather than part of this gap, and closing it would mean designing a keyboard affordance
   for the treemap — new design work, not a targeted fix to already-shipped code.
</planner_assumptions>
