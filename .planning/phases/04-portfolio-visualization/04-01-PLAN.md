<objective>
Put a live sparkline in every watchlist row. One shared client-side price-history buffer,
filled inside the SSE handler the app already has, feeds one small chart component embedded
in the existing row.

Purpose: this is the phase's tracer. It proves the whole charting architecture end-to-end —
a new runtime dependency (Recharts) rendering inside this Next.js static-export build, an
SVG chart sized correctly inside an existing dense flex row, and a new slice of SSE-derived
state living beside `prices`/`firstPrices` without forking the single-connection rule. Every
later plan in this phase (main chart, heatmap, P&L chart) builds on exactly these pieces, so
proving them on one small surface first is what keeps a wrong turn to one commit.

Output: `recharts` installed, `chartTheme.ts` (shared constants + the one trend rule),
`priceHistory` in `priceStore.tsx`, `Sparkline.tsx`, and a watchlist row that shows it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE tick payload → client chart state | Server-pushed JSON is parsed and accumulated into long-lived browser state that drives SVG rendering |
| ticker symbol → SVG accessible name | A server-supplied string becomes an `aria-label` on a rendered element |
| npm registry → build output | A new third-party runtime dependency enters the production bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `Sparkline.tsx` accessible name and any chart text | medium | mitigate | The label is built by JSX/string interpolation, which escapes by default; a negative grep asserts no raw-HTML injection anywhere under `frontend/components/charts/`. Ticker symbols are additionally constrained server-side to the simulator's fixed universe (root PLAN.md §6). |
| T-04-02 | Denial of Service | `priceStore.tsx` `priceHistory` buffer | medium | mitigate | Each ticker's series is capped at `PRICE_HISTORY_LIMIT = 500` with oldest-first eviction, so an all-day session cannot grow client memory without bound. Asserted by grep on both the constant and its application. |
| T-04-SC | Tampering | `npm --prefix frontend install recharts` | high | mitigate | `04-RESEARCH.md` §Package Legitimacy Audit records a completed audit for the single package this phase installs — verdict OK (official `github.com/recharts/recharts` repo, ~43M weekly downloads, no postinstall script, peer range includes React 19). | T-04-03 | Information Disclosure | rendered price series | low | accept | The sparkline displays prices already shown numerically in the same row and streamed to this browser anyway; no new data leaves the client. |

   map in one context is negligible, and keeping every SSE-derived slice in the file that owns
   the connection is the simpler invariant to defend. Every later plan in this phase imports
   `usePriceStore()` for history — do not add a second provider for it.
2. **The zero-point baseline is a plain element, not a Recharts render.** The UI-SPEC asks for a
   "flat muted baseline"; drawing that through `LineChart` with an empty dataset invites the
   zero-height/blank-chart failure mode for no benefit. A bordered div is the honest
   implementation of "nothing has happened yet".
3. **Flagged edge-probe assumption (UI-02, unresolved rows).** The deterministic edge probe left
   the UI-02 `adjacency`, `empty`, and `ordering` rows unresolved. All three are resolved here
   as explicit `must_haves.truths` (equal adjacent samples merge; 0-point and 1-point states are
   specified; arrival order is never re-sorted). Flagging the resolution so UAT can overturn it:
   if the intent was instead to record every heartbeat including unchanged ones, this plan is
   wrong and the merge rule is the thing to change.
</planner_assumptions>
