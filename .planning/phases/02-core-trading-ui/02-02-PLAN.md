<flash_trigger_correction>
**Read this before writing `PriceCell`.** `planning/PLAN.md` §6, the docstring on
`PriceCache.update()` in `backend/app/market/cache.py`, and 02-RESEARCH.md's Anti-Patterns section
all suggest testing `tick.price !== tick.previous_price` to decide whether to flash. That test is
wrong on its own, and following it produces a cell that flashes on every heartbeat forever.

The reason is in `PriceCache.update()` itself: when an observed price equals the last known price,
the cache emits a tick that keeps the **old** `previous_price` rather than collapsing it to the
current price. So after any real move from 100 to 101, every subsequent heartbeat re-broadcasts
`price: 101, previous_price: 100` — `price !== previous_price` stays true indefinitely, and the SSE
route re-sends that same cached tick every 0.5 seconds whether or not anything moved.

The correct trigger is the one in 02-PATTERNS.md's `PriceCell` code: **flash when the incoming
price differs from the price this cell last rendered**, tracked in a `useRef`. The tick's
`direction` field picks the color (it is freshly computed on exactly the ticks that represent a
real move). Do not use `previous_price` as a per-event change signal anywhere.
</flash_trigger_correction>

component performs no other arithmetic on the value.

PLAN.md §2 palette names no gain/loss pair, and 02-RESEARCH.md Open Question 1 leaves this

emits them; do not assemble a class name from string concatenation of a color fragment.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Tampering | `WatchlistRow.tsx` rendering backend-supplied ticker symbols | low | mitigate | Ticker strings are rendered as JSX text children and are escaped by React; no raw-HTML rendering path exists under `frontend/`, enforced by the repository-wide check in Plan 02-01 |
| T-02-06 | Denial of Service | `usePriceStore()` consumers | low | mitigate | Consumers read the single shared connection; an acceptance check asserts `new EventSource` appears only in `frontend/lib/priceStore.tsx`, so N watchlist rows can never become N backend SSE connections |
| T-02-07 | Tampering | `JSON.parse` of the SSE `data` payload in the shared store | low | accept | The payload originates from the same-origin FastAPI backend in production and from an explicitly allow-listed local origin in development; it is not user-supplied content, and no `eval`-class parsing is used |
| T-02-08 | Spoofing | Simulated prices presented as market data | low | mitigate | Change-percent column labelled as session-relative rather than implying a market-day figure; the broader "this is a simulated account" labelling lands with the header in Plan 02-03 |

No package-manager installs occur in this plan, so no package-legitimacy gate applies; the versions
vetted in Plan 02-01 are unchanged.
