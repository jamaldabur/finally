<objective>
**As a** user of FinAlly, **I want to** start the entire application with a single command and have
my data persist across restarts, **so that** I get the one-command trading terminal Phase 5
promises — without my local API keys being baked into a Docker layer, without a spurious error on
every shutdown, and without a start script that can hang or dump a stack trace at me.

This is a gap-closure plan. Phase 5 verified 9/10 must-haves; the tenth — "no secret ever enters a
Docker image layer via the build context" (Plan 05-01, T-05-01) — failed. `.dockerignore`'s bare
env-file line is root-anchored in Docker's pattern semantics, so it never covered
`.env.<suffix>` variants or a bare dotenv file below the root, and `Dockerfile:10`'s blanket
`COPY frontend/ ./` copied the on-disk `frontend/.env.development.local` into the `frontend-build`
layer. Both 05-REVIEW.md (CR-01) and 05-VERIFICATION.md confirmed it independently. The same review
also found three reviewer-verified warnings with evidenced fixes: an un-awaited task cancellation
racing the Massive client's close on shutdown (WR-01), an unbounded readiness `curl` in the bash
launcher (WR-02), and five terminating error calls in the PowerShell launcher that dump an
exception block and make their `exit 1` dead code (WR-03).

Plan-time grounding (performed while planning, in a scratch context outside the repository, with
empty dummy files only): the three-line `**/.env` / `**/.env.*` / `!**/.env.example` form left
exactly the two template files in the context; the current bare line let through a nested bare
`frontend/nested/.env`, `.env.<suffix>` files at the root, in `frontend/`, and in `backend/app/`.
Docker's `.dockerignore`, unlike `.gitignore`, anchors a slash-free pattern to the context root —
05-REVIEW.md's "matches at any depth" wording is slightly off, and the broadened fix covers both
readings. The WR-03 exception block was also reproduced live at plan time from a temp copy of the
script.

three warnings while the files are open, so Phase 5 can re-verify at 10/10.

ordering fix in `backend/app/main.py` with a regression test; one curl flag in `start_mac.sh`; five
stderr writes in `start_windows.ps1`; and a live round trip showing the whole thing still starts,
serves, and stops cleanly.

Task 1 is the tracer: the blocker's end-to-end slice from the repository working tree, through the

reviewer-verified defect fixes that expand from it, and Task 3's round trip exercises all three
tasks' changes together in one rebuilt image.
