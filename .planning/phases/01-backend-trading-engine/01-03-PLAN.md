## Locked API contract (decided here; `planning/PLAN.md` §8 names the endpoints but not their JSON)

**`GET /api/watchlist`** → 200
`{"watchlist": [{"ticker": "AAPL", "price": 190.12, "previous_price": 189.90, "direction": "up", "timestamp": "2026-…"}]}`
Entries are sorted alphabetically by ticker for deterministic output. `price`, `previous_price`,
`direction` and `timestamp` are `null` for a ticker the cache has not priced yet (freshly added, or
before the first update-loop cycle).

**`POST /api/watchlist`** body `{"ticker": "pypl"}` → 200
`{"ticker": "PYPL", "added": true}` — `added` is `false` when the ticker was already on the list
(idempotent add, no error). Unrecognized symbol → 400 `{"detail": "Unknown ticker: ZZZZ"}`, matching
the message prefix Plan 01 locked for the trade route.

**`DELETE /api/watchlist/{ticker}`** → 200 `{"ticker": "AAPL", "removed": true}` — `removed` is
`false` when the ticker was not on the list (idempotent delete, no 404). No validity check is
applied on delete; an unrecognized symbol simply is not found.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → `POST /api/watchlist` | Untrusted `ticker` string in a JSON body crosses here |
| HTTP client → `DELETE /api/watchlist/{ticker}` | Untrusted `ticker` in a URL path segment crosses here and becomes a SQL delete predicate |
| Route → SQLite (`db/finally.db`) | Caller-supplied ticker reaches the `watchlist` table |
| Watchlist table → `run_update_loop` | An added ticker becomes an argument to the live market data source on the next cycle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `INSERT OR IGNORE` / `DELETE` in `app/db/watchlist.py` | high | mitigate | `?` placeholders with a params tuple on both new statements, matching the file's three existing statements; the URL path segment never reaches SQL as interpolated text |
| T-01-03 | Tampering | `POST /api/watchlist` request body | medium | mitigate | Pydantic `ticker: str = Field(min_length=1)` rejects an empty body value at the FastAPI layer (422) before normalization |
| T-01-04 | Tampering | Unrecognized ticker entering the `watchlist` table and then the market data source | high | mitigate | `_normalize()` then `await market_source.is_valid_ticker(ticker)` gates every add; only `TICKER_UNIVERSE` members can be persisted, so `run_update_loop` never asks either source for an arbitrary caller-supplied symbol |
| T-01-08 | Tampering | Unicode/whitespace ticker variants creating duplicate rows that bypass `UNIQUE(user_id, ticker)` | medium | mitigate | A single shared `_normalize()` (`.strip().upper()`) is applied at the route boundary on all three endpoints, so the canonical uppercase form is the only string that ever reaches the unique index |
| T-01-09 | Denial of Service | Unbounded watchlist growth enlarging every update-loop poll | low | accept | Adds are capped by `TICKER_UNIVERSE` (30 symbols) for the simulator; the Massive client's own polling cadence and error handling already absorb a larger ticker set.
