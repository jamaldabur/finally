## Locked API contract (decided here; `planning/PLAN.md` §8 names the endpoints but not their JSON)

**`GET /api/portfolio`** → 200
```
{
  "cash_balance": 9000.0,
  "positions": [
    {"ticker": "AAPL", "quantity": 10.0, "avg_cost": 100.0, "current_price": 120.0,
     "market_value": 1200.0, "unrealized_pnl": 200.0, "pct_change": 20.0}
  ],
  "positions_value": 1200.0,
  "total_value": 10200.0,
  "total_unrealized_pnl": 200.0
}
```
Positions are sorted by ticker. `total_value == cash_balance + positions_value`.

**Mark-to-cost fallback** (locked): a position whose ticker has no entry in `PriceCache` — reachable
by buying a ticker and then removing it from the watchlist, since `run_update_loop` only prices
watched tickers — reports `current_price: null`, `market_value: quantity * avg_cost`,
`unrealized_pnl: 0.0`, `pct_change: 0.0`. The position stays in `positions_value` at cost rather than
silently dropping out of `total_value`.

**`GET /api/portfolio/history`** → 200
`{"snapshots": [{"total_value": 10000.0, "recorded_at": "2026-…"}]}` — ascending by `recorded_at`.
Rows are never pruned; `planning/PLAN.md` §7 explicitly accepts unbounded growth for this
single-user demo.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → `GET /api/portfolio`, `GET /api/portfolio/history` | Read-only; no caller-supplied value reaches SQL (no query parameters are accepted) |
| Background snapshot task → SQLite | An unattended writer runs for the process lifetime, outside any request |
| `execute_trade()` locked section → `compute_portfolio_view()` | A nested call inside a held non-reentrant lock |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | SQL in `app/db/portfolio_snapshots.py` | high | mitigate | `?` placeholders with a params tuple on both the insert and the select, matching `app/db/watchlist.py`; the read endpoints accept no query parameters, so no caller value reaches SQL at all |
| T-01-02 | Tampering | Snapshot value recorded during a concurrent trade | high | mitigate | The snapshot-on-trade insert happens inside the same `async with lock:` block as the cash and position writes, so the recorded `total_value` is exactly the state this trade committed and no interleaved trade can shift it first |
