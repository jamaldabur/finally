<objective>
Close G-03-5 and G-03-6 with one structural change: in `execute_llm_actions()`, normalize each
LLM-proposed item exactly once and make validation, execution and annotation all read that one
result.

Purpose: both gaps are the same defect wearing two faces. The validators normalize with a strip
and a case fold; the executor separately re-derives the same fields with only a case fold. The
value that got validated is therefore not always the value that gets executed. G-03-6 is the
severe face of it and was confirmed live: an action of " add" with a leading space — exactly the
kind of padding real backing models were observed producing in the same investigation — passes
validation as "add", then fails an equality check against the literal "add" in the executor,
falls into the else branch, and calls the REMOVE function. A watched ticker was deleted and the
user was shown a green "executed" badge. G-03-5 is the reported face: a backing model encoded
"sell 2" as side sell with quantity -2, and the validator discarded the whole item on a sign
that was merely redundant with a side it had already stated correctly.

Fixing only the two reproduced instances would leave the divergence itself in place. Normalizing
once and reusing closes the class.

Layered on top: a sell-only sign recovery for G-03-5, and a preventive layer — field
descriptions in the emitted JSON Schema plus one matching prompt rule. The preventive layer was
A/B tested live and measurably reduces how often the bad item is produced at all, but it is not
sufficient alone, because the free auto-router serves a different backing model per call and is
non-stationary by construction. Recovery and prevention address different stages; neither
replaces the other.

Output: an `actions.py` where a validated value and an executed value are provably the same
object, a schema and prompt that tell the model what the sign convention is, and regression
tests that construct schema items directly because the mock path structurally cannot reach any
of these inputs.
</objective>
