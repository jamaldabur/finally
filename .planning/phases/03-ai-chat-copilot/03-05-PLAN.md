<objective>
Close G-03-1 and G-03-2: make the chat panel's collapse control something a user can find,
recognise as a control, and watch respond. The toggle was never functionally broken — the
debug session eliminated every functional candidate with direct evidence — so this plan
fixes what actually failed: a rail that is visually absent at 1.109:1 against the page, a
collapse trigger that is a chromeless ~50x16px text span, no hover feedback anywhere on the
rail, and no transition in either direction.

Purpose: the root cause is `03-UI-SPEC.md`, which specified each of these defects and which
the executor implemented faithfully. Fixing only the component would leave the code out of
contract with its own spec, so the spec is amended first and the component then implements
it. A secondary dead-code defect — the unread dot whose only reachable trigger is a false
positive on pre-existing history — is folded in.

Output: an amended `03-UI-SPEC.md` collapse-control contract, and a `ChatPanel.tsx`
restructured from two disjoint conditional subtrees into one persistent element whose width
animates.
</objective>

<planner_assumptions>
1. **The rail's edge, not its fill, carries the 3:1 contrast.** WCAG 1.4.11 requires the
   visual information identifying the component to clear 3:1; on a `#0d1117` page that
   forces a fairly light element, and lifting the *fill* that far would make a 48px rail the
   brightest surface on screen, competing with the chat content it is standing in for.
   Putting the ratio on the edge (the muted-text token, about 6.2:1) satisfies the criterion
   with the element the user actually reads as the rail's boundary, and keeps the surface
   consistent with every other panel. No new theme token is introduced.
2. **`frontend/app/page.tsx` is deliberately out of scope.** The debug session flagged the
   row's `p-6` padding as making the rail float 24px inside the viewport edge, but recorded
   it as "contributing, not primary", and it appears in no gap's `missing` list. Changing the
   shared three-column padding to dock one rail would move a layout decision that Phase 2
   locked, for a secondary effect. If the rail still reads as floating at the human check,
